## 10:38 解决 CDP WebSocket 403 Forbidden 及弹窗三连问题
- **用户诉求**：点击【抓取职位】时依旧弹出第 3 个 Chrome 窗口，且日志报 `Handshake status 403 Forbidden` 拒绝连接；用户质疑“为什么还在弹窗，看一下以前的日报”。
- **原因复盘**：
  1. 之前以为必须在 Chrome 启动命令行加 `--remote-allow-origins=*`，但如果用户已经启动了带 9222 端口的 Chrome（第 2 个窗口），Python 的 `websocket-client` 在发起 WebSocket 握手时会默认附带 `Origin: http://127.0.0.1:9222`，触发 Chrome 111+ 的源校验被拒绝 (403)。
  2. 当 `boss_cdp_raw.py` 连接 9222 端口遇到 403 失败后，它触发了底层的兜底机制，试图新建一个全新的 Chromium 窗口（第 3 个弹窗），导致画面弹窗不断。
- **解决方案**：
  1. 在 `boss_cdp_raw.py` 的 `CDPSession` 初始化代码中，给 `websocket.create_connection` 添加了 `suppress_origin=True` 参数。
  2. 此参数会在 WebSocket 握手阶段完全**屏蔽/抹去 `Origin` 请求头**。Chrome 对没有 `Origin` 头的非浏览器/原生客户端请求不会进行 `remote-allow-origins` 拦截，从而直接透传连接。
  3. 将修改后的 `boss_cdp_raw.py` 成功同步部署到了 MacMini。
- **结果**：Python 脚本现在可以直接、静默地通过 CDP 连上用户第 2 个已登录的 Chrome 实例，再也不会出现 403 错误，也绝不会触发第 3 个弹窗。
- **验证方式**：同步脚本到远端并提示用户重新触发抓取。
- **生成产物**：更新后的 `scripts/boss_cdp_raw.py`。
- **遗留问题**：无。
